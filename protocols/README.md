# Review protocols — wording is Dan's; v1 is generated verbatim

Each file here is a versioned review protocol: the "production request" prompt a
review tier receives, derived from the official TREC topic language.

Rules (mirrored in CLAUDE.md):

- v1 of each topic is generated by `python -m pipeline protocol`: the official topic
  text pasted verbatim into fixed, topic-independent boilerplate (see
  `pipeline/review/protocol_gen.py`). It adds no interpretation, which keeps v1
  comparable to the 2023 baseline. A test fails if a generated v1 is hand-edited.
- Everything after v1 is Dan's: Claude Code must never hand-edit a protocol or
  write v2+. Prompt iteration = Dan writes (or explicitly signs off on) a new
  `<topic>.vN.md`; old versions stay in place so every decision-log entry's
  `prompt_version` resolves.
- File naming: `enron/topic201.v1.md`, `bush/athome401.v1.md`,
  `privilege/enron_priv.v1.md`. The pipeline records both the version (from the
  file name) and a content hash with every decision; changing a file's content
  without bumping its version will fail the prompt-drift golden test.
- A protocol contains: the production request (official topic text), responsiveness
  definitions, the output JSON contract (decision / confidence / rationale ≤ 2
  sentences, no verbatim quotes from documents), and borderline guidance.
